Principles of Programming

Programming Skills Workshop - 3rd March 2026

KISS

Keep It Simple, (Stupid)

Anti-patterns

  • Nested conditionals, "arrow code"
  • Long methods, large classes
  • Pieces of code that need a comment to explain what they do

Cyclomatic Complexity

  • Measures the number of independent paths through a program's source code
  • Increases with more conditionals, loops, logical operators
  • Makes code harder to test, debug and maintain

Takeaway

Aim for the simplest solution that works

DRY

Don't Repeat Yourself

Anti-patterns

  • Copy-pasted code
  • Fixing the same bug more than once
  • Functions with similar names

Takeaway

Extract repeated logic into reusable functions or classes

YAGNI

You Aren't Gonna Need It

Anti-patterns

  • Configs and kwargs that are never changed
  • Premature generalisation
  • Over-engineering e.g. an ABC with one implementation

Takeaway

Ask yourself: "Do I really need this feature right now?"

SOLID - object oriented principles

  • Single Responsibility Principle (SRP)
  • Open/Closed Principle (OCP)
  • Liskov Substitution Principle (LSP)
  • Interface Segregation Principle (ISP)
  • Dependency Inversion Principle (DIP)

Liskov Substitution Principle

Objects of a superclass should be replaceable with objects of a subclass without breaking the program

  • Subclasses should adhere to the contracts defined by their superclass
  • Subclasses should not have stricter requirements on inputs
  • Subclasses should not have looser constraints on their outputs

							class Bird:
								def fly(self):
									print("Flying")


							class Duck(Bird):
								def fly(self):
									print("Duck flying")


							class Penguin(Bird):
								def fly(self):
									raise NotImplementedError("Penguins can't fly")
							

							def make_it_fly(bird: Bird):
								bird.fly()

							make_it_fly(Duck())
							# Duck flying

							make_it_fly(Penguin())
							# NotImplementedError: Penguins can't fly

Takeaway

Design your class hierarchies with inheritance contracts in mind

Summary

  • KISS, DRY, YAGNI, LSP are all guidelines, not hard rules
  • Sometimes there is tension between different principles
  • Think of KISS and YAGNI upfront and DRY and LSP when refactoring

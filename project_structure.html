Overall structure

  • Details are a matter of personal preference but having a system is key
  • Example subdirectories may include: data, env, configs, results

Managing project dependencies

  • Use virtual environments (e.g., conda, venv)
  • Keep versions frozen by default
    • Update dependencies when required
    • Caveat: this advice immediately changes as soon as you are writing code that others are going to use

Building workflows

  • Snakemake works - other workflow managers are available
  • Designing your code to run with Docker really helps

Tracking results

  • Again details are a matter of personal preference but some general principles:
    • Keep a log book, why and when you tried a certain thing
    • Make your git history descriptive, git is a powerful historical tool
    • Record configs for your experiments e.g. through git history
